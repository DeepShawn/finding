# 技术说明与维护

## 数据与责任边界

`puzzles.js` 负责唯一的游戏进度。原版 `ROOMS / NOTES / ITEM_DATA / STAGES`、五道机关、三个结局、扣时规则、证词和 localStorage 均保留。新增 `window.Ward` 为外层提供受控入口；不复制第二套解谜状态。

`worlds.js` 中的 `Builder` 提供几何、材质、点光源、热区、碰撞体、平面道具、入口和菜单预览机位。五个房间是五个独立实例，各自建立空间，不是替换同一背景。切换房间通过地点栏完成，不是走过门后无缝载入大地图。

`app.js` 持有玩家位置和视角表现。`worldPositions` 和 `viewMode` 随原存档序列化。`ward:scene` 同步谜题状态到外层；`ward:modal` 释放鼠标锁定、停止移动；`ward:scare` 扩展原版惊吓。

## 三种画面

### Native WebGL 2

没有 Three.js、Babylon.js 或游戏引擎运行包。矩阵、相机、几何合批、纹理上传和 Shader 位于 `engine.js`。

- 顶点按材质静态合批。每个房间初始化一次并缓存。
- 四个点光源，Lambert 漫反射与简化高光。
- 一个静态深度阴影贴图，PCF 采样；不是所有灯均投影。
- 相机方向手电光锥。手电不另建动态阴影贴图。
- 距离雾、半透明光柱网格、地面水痕、透明玻璃和接触暗面。
- 最多 240 个深度测试微尘点；性能优先时不绘制。
- 离屏颜色缓冲加后处理：轻微辉光、暗角、颗粒、色散与亮度。
- 高画质 / 均衡 / 性能优先用不同内部像素比例，设备像素比上限 1.5；性能优先不采样阴影。

这是轻量风格化三维，不是物理光线追踪、照片级资产、实时反射或体积光散射模拟。镜面和雨窗是专门绘制的材质；地面高光不是平面实时倒影。镜子没有实时复制玩家。幽影是预设的透明几何和事件，不是可追逐玩家的 AI 敌人。所有这些边界都不影响解谜完整性。

### Canvas 2D

二维不是固定截图，也不是三维正交相机。它从 `props / colliders / hotspots` 渲染独立房间平面：家具、书架、床、墙、灯、玩家、手电范围、路线和交互标记。

A* 使用 0.30 米网格和八方向移动，对角线禁止穿角；玩家半径约 0.235 米。点线索时选附近可站立且不被交互遮挡的目标位置。手动移动会取消路线。碰撞沿 X、Z 轴滑动处理，属于轻量导航，不是刚体物理系统。

### 经典调查

保留原版 SVG 场景与 HTML 弹窗，以同一 `inspect(id)` 进入谜题。三维中的小字不要求玩家勉强辨认：重要文字都会在调查弹窗和线索本中清晰显示。

## 音效和舒适设置

Web Audio 经第一次用户手势启动。各房间采用不同滤波噪声和低频基音，脚步、环境异响在本地合成；没有外部录音或自动播放资源。设置可关闭声音、人影惊吓、胶片效果和镜头运动，并调整画质、亮度、转向灵敏度。程序没有快速全屏频闪。

原生 API 失败时做降级：WebGL 2 不可用切到 2D；鼠标锁定失败仍支持拖动环顾；全屏不允许时保留普通窗口；存储异常不阻止当前局继续。

## 存储

- `silent-ward-save-v1`：原游戏存档，加上 `worldPositions` 和 `viewMode`。
- `silent-ward-prefs-v1`：声音、惊吓开关。
- `silent-ward-presentation-v2`：画质、亮度、灵敏度和视角偏好。

位置约每 3.5 秒写回状态，原逻辑约每 5 秒持久化；解谜、暂停、视角切换等也保存。正常结束会清除未完成存档。当前浏览器不同域名、HTTP / HTTPS、端口、离线文件不会自动共享存档。

## 扩展房间

1. 在 `puzzles.js` 注册房间、热点、所需锁定和谜题状态；保持热点 ID 唯一。
2. 在 `worlds.js` 添加 `sceneMeta` 与场景构建函数，设置 `bounds / spawn / preview / look`。
3. 放置网格、灯、碰撞体；每个 `hotspot(id, label, position)` 对应原谜题的 `inspect(id)`。
4. 为主要物体加 `prop`，用于二维和迷你地图。
5. 验证入口不在碰撞体中，每个热点至少有一个可到达的接近位置。
6. 补菜单缩略图并运行 UI 和导航测试。

需要调整美术时，先改 `palettes / surface / textTexture`，再改灯光和机位。不要仅增加亮度来掩盖无法辨认的交互点；文字信息应保留弹窗版本。

## 安全与托管

无秘密密钥、服务端、账户系统或网络上报。谜题答案在客户端源码中可以查到；这是离线单机游戏，不能用于可信排行榜或防作弊竞赛。原生代码和所有素材通过同站点相对路径加载，适合 GitHub Pages 项目子目录。

没有 Service Worker，以免新版本部署后长期加载陈旧缓存。离线使用 `dist/` 中的单文件副本；部署更新以 `src/` 为源，再运行工具重建离线版本。
