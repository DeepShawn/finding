# 技术说明与维护

## 数据与责任边界

`puzzles.js` 负责唯一的游戏进度。原版 `ROOMS / NOTES / ITEM_DATA / STAGES`、病院五道机关、扣时规则、证词和 localStorage 均保留。新增 `window.Ward` 为外层提供受控入口；不复制第二套解谜状态。

`worlds.js` 中的 `Builder` 提供几何、材质、点光源、热区、碰撞体、平面道具、入口和菜单预览机位。病院五个房间是五个独立实例，各自建立空间，不是替换同一背景。切换房间通过地点栏完成，不是走过门后无缝载入大地图。

`app.js` 持有玩家位置和视角表现。`worldPositions` 和 `viewMode` 随原存档序列化。`ward:scene` 同步谜题状态到外层；`ward:modal` 释放鼠标锁定、停止移动；`ward:scare` 扩展原版惊吓。

`campaign-data.js` 是四个新增章节的内容源；每区含尺寸、类型、两份记录、主机关、奖励和可选证词。`campaign.js` 把它们注册进原始 `ROOMS / NOTES / ITEM_DATA`，并在选章时原位替换 `STAGES`，不建立与旧 UI 脱节的第二份进度。

`worlds-extra.js` 使用 `WorldKit` 的模型组件注册二十个新增场景工厂。房间尺寸、家具和碰撞来自各自配置；共享材质缓存减少重复纹理。`campaign-shots.js` 保存开发工具捕获时的热区投影坐标，经典调查用固定可读标签和指示线对应真实物件。

## 三种画面

### Native WebGL 2

没有 Three.js、Babylon.js 或游戏引擎运行包。矩阵、相机、几何合批、纹理上传和 Shader 位于 `engine.js`。

- 顶点按材质静态合批。每个房间初始化一次并缓存。
- 四个点光源，Lambert 漫反射与简化高光。
- 一个静态深度阴影贴图，PCF 采样；不是所有灯均投影。
- 相机方向手电光锥。手电不另建动态阴影贴图。
- 距离雾、半透明光柱网格、地面水痕、透明玻璃和接触暗面。
- 最多 240 个深度测试微尘点；性能优先时不绘制。
- 离屏颜色缓冲加后处理：轻微辉光、暗角、颗粒、色散与亮度。
- 高画质 / 均衡 / 性能优先用不同内部像素比例，设备像素比上限 1.5；性能优先不采样阴影。

这是轻量风格化三维，不是物理光线追踪、照片级资产、实时反射或体积光散射模拟。镜面和雨窗是专门绘制的材质；地面高光不是平面实时倒影。镜子没有实时复制玩家。幽影是预设的透明几何和事件，不是可追逐玩家的 AI 敌人。所有这些边界都不影响解谜完整性。

### Canvas 2D

二维不是固定截图，也不是三维正交相机。它从 `props / colliders / hotspots` 渲染独立房间平面：家具、书架、床、墙、灯、玩家、手电范围、路线和交互标记。

A* 使用 0.30 米网格和八方向移动，对角线禁止穿角；玩家半径约 0.235 米。点线索时选附近可站立且不被交互遮挡的目标位置。手动移动会取消路线。碰撞沿 X、Z 轴滑动处理，属于轻量导航，不是刚体物理系统。

### 经典调查

病院保留原版 SVG 场景；新增四章使用开发时由实际三维场景捕获的本地 WebP 和投影指示线，全部使用 HTML 弹窗，以同一 `inspect(id)` 进入谜题。三维中的小字不要求玩家勉强辨认：重要文字都会在调查弹窗和线索本中清晰显示。

## 音效和舒适设置

Web Audio 经第一次用户手势启动。各房间采用不同滤波噪声和低频基音，脚步、环境异响在本地合成；没有外部录音或自动播放资源。设置可关闭声音、人影惊吓、胶片效果和镜头运动，并调整画质、亮度、转向灵敏度。程序没有快速全屏频闪。

原生 API 失败时做降级：WebGL 2 不可用切到 2D；鼠标锁定失败仍支持拖动环顾；全屏不允许时保留普通窗口；存储异常不阻止当前局继续。

## 存储、数据验证与迁移

| 存储键 | 用途 |
|---|---|
| `silent-ward-campaign-v3` | 五章的未完成运行、最佳证据记录和当前选章 |
| `silent-ward-active-v3` | 兼容旧核心的当前活动存档镜像 |
| `silent-ward-save-v1` | 仅作为首次迁移输入，不覆盖删除 |
| `silent-ward-prefs-v1` | 声音与惊吓偏好 |
| `silent-ward-presentation-v2` | 沿用 v2 的画质、亮度、灵敏度与视角偏好 |

`profile.runs[chapterId]` 是一章完整状态；`state.puzzleState[puzzleId]` 是机关尚未验证的排列、拨盘、灯阵或路线。位置由原视角层写入，进度由核心持久化。改动机关、切换视角、暂停与周期保存都会调用同一存储入口。正常撤离或失败清理的是当前章的运行，不是其他章节或最佳记录。

战役档案在主菜单提供 JSON 导出与导入。导入限制文件为 1 MB 以内，先解析并确认，再替换记录。运行模式、房间、物品、证词、数值和各类型中间状态做白名单/范围校验；不合法中间状态重置，未通过运行结构校验的章节被忽略。它是容错逻辑，不是加密、签名或防作弊。

首次启动尝试读取同站点旧版存档；`migratedV2` 标记避免通关后再把旧进度“复活”。站点不同、隐私模式、禁用存储、清除数据或离线文件变化不会自动同步。没有服务器保存副本；需要跨浏览器时使用备份功能。

## 新谜题控制器

`campaign.js` 中 `initial / isCorrect / puzzleAction` 分离初始化、验证和操作。支持 `code / order / memory / balance / dials / mix / linked / lights / route` 九种类型。数字与字母密码保持字符串，保留前导零；路线坐标和按钮内部从 0 编号，玩家可见数字从 1 编号；模数联动按矩阵累计。

每道新机关用固定 ID `cx_<chapter>_<1..5>`。附属热区为 `_clue0`、`_clue1`、可选 `_evidence`、最后区域 `_exit`。奖励物品为 `_item`。新增区域只在前一机关通过后开放；客户端源码可修改状态，不提供安全边界。

记忆谜题同时高亮和显示文字。声音完全可选，800 ms 的单项呈现与 180 ms 间隔不是全屏闪烁。动画令牌在重置或切换时废弃，避免异步播放污染新谜题。

## 扩展章节或区域

1. 在 `campaign-data.js` 定义章节、五个区域、谜题和记录。当前战役 UI 按五章 / 每章五区设计；要进一步改变数量，应同时参数化进度、归档总数和显示文案，而非仅追加 JSON。
2. 在 `worlds-extra.js` 的场景装饰分支新增几何组件，配置尺寸、主题材质、灯光和摄像机。
3. 交互点必须对应真实可到达的位置；新增几何需同时登记 `colliders` 和 `props`。透明装饰与纯顶部吊件不必阻挡玩家。
4. 运行 `tools/capture_scenes.py` 更新调查图及热区投影，再运行 `tools/build_standalone.py` 更新离线版。
5. 更新 `campaign_flow.py` 的实际答案流程，跑三视角、导航、触控和静态资源检查；修改截图时以新的 UI 截图更新文档。

不要只调亮度来掩盖交互不可辨认；所有关键记录都应有弹窗文字。场景捕获工具会使用明确的预览状态与摄影机，不将测试解锁代码注入发布游戏。

## 安全与托管

无秘密密钥、服务端、账户系统或网络上报。谜题答案在客户端源码中可以查到；这是离线单机游戏，不能用于可信排行榜或防作弊竞赛。原生代码和所有素材通过同站点相对路径加载，适合 GitHub Pages 项目子目录。

没有 Service Worker，以免新版本部署后长期加载陈旧缓存。离线使用 `dist/` 中的单文件副本；部署更新以 `src/` 为源，再运行工具重建离线版本。
