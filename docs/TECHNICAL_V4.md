# v4 技术说明

## 模型和状态

`depth-model.js` 不读写 DOM、存档或网络。输入是版本内种子、章节、区域索引和强度，输出题面、规则、参考解、回执和回签规则。可以由 Node `require()` 或浏览器 `DepthModel` 使用。

生成策略：时间差连通图；房号循环约束与双重双射；字典/位置/偏移转译；带唯一性检验的数织；从已知按法逆生成的翻灯矩阵；先生成可行路径再生成检查点、禁行格、步数和权重；严格对角占优整数方程；素数模下可逆联动矩阵；枚举检查唯一固定点的真假证言。

种子不会改变原场景、基础机关答案或证词文本。游戏保留公开参考解以支持提示和离线开发检验，不提供反作弊保证。流程中的真假记录与现实身份、医疗或实验设施无关。

`depth.js` 管理局部状态和区域依赖。主要对象：

```text
state.depth = {
  version: 1,
  level: 'abyss' | 'nightmare',
  seed: string,
  analysed: boolean[5],
  audits: boolean[5],
  read: ('l0'..'l4' | 's0'..'s4' | 'f')[],
  ui: { 0..4: controller-specific state },
  auditInput: { 0..4: string },
  hints: { taskKey: level },
  hintSpent: number,
  echo: number,
  scratch: string,
  events: number
}
```

存档不需要复制题面。继续调查时根据种子重新生成题面，并把持久化的未提交输入经过各控制器的形状、范围校验。病院与扩展章节都使用同一份深层状态。

## 与原版集成

- `startGame` 在绘制与首次保存前调用 `Depth.prepareState`。
- `currentStage` 在高难度返回有序的下一项依赖任务。
- `inspect` 保留原始正文，在文字线索下追加深层夹层；未完成分析时拦截原机关入口。
- 基础密码、档案、电路、扩展机关的提交还会再次验证分析前置条件。
- `goRoom` 在高难度使用严格区域顺序；已开放区域可反复返回。
- `Campaign.finish` 在高难度全部 15 节点完成前拒绝撤离。
- `penalty`、`openHint`、`revealHint` 依据本轮强度处理惩罚与额度。
- 3D/2D 的 HUD 和经典调查侧栏显示同一份进度。

新增取证资料放在既有区域的资料夹和终端界面里，没有新增碰撞体或渲染器。实际空间仍为原来的 25 个房间。界面控制的核验检查所在区域；远程矩阵可读旧资料、查看目标、快速切换开放区域，不是无缝步行世界。

## 持久化兼容

战役存储键沿用 `silent-ward-campaign-v3`，战役容器版本沿用 3，以可选 `depth` 字段扩展本章记录。菜单偏好另存 `silent-ward-depth-prefs-v4`。基础存储键保持旧行为，章节档案是完整战役记录的主来源。

没有深层字段的旧存档按经典模式继续。JSON 导入仍验证基础字段；恢复本章时深层字段进一步清洗。时限上限按深层强度计算，避免旧验证器把 54 分钟错误裁成原本 18 分钟。

经典 / 深渊 / 噩梦不共享三份独立进行中存档，同一章只能有一个进行中槽位。提示开销和草稿随当前槽位一起保存。

## 布局与可用性

原生按钮、select、文本输入、表单提交和可滚动模态框。数织明确区分未知、实格、空格；真假证言明确显示未知/真/假；路线同时显示节点编号和采样值。深层逻辑不需要声音或颜色作为唯一线索。

小屏幕矩阵变为单列，数织缩放到可见范围，原有移动摇杆和视角按钮保持存在。狭窄手机上的 7×7 数织格子小于普通大按钮，横屏或经典调查视角更便于操作；没有声称完成无障碍标准认证。

## 稳定性边界

模型的可解性、唯一性和 UI 流程测试是分开的。数织与真假证言生成时检查唯一性；路线与翻灯等题型接受所有满足规则的解。参考路径不等于唯一被允许的路径。

本版没有服务端或篡改检测。恶意改写源码、运行控制台或伪造备份能够跳过谜题，这是纯离线游戏的设计边界，不是安全防护功能。用户导入的草稿和文本进入 HTML 前会转义。
